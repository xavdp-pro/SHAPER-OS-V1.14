# What is a "bridge"?

A **bridge** is a small local HTTP server (Node.js) bridging
**KovZu** (the web API/UI) and **a real CLI agent** (`cursor-agent` or `claude`)
running headless on a machine. It acts as a translator: KovZu speaks
HTTP/JSON, while the CLI agent speaks stdin/stdout in `stream-json`.

## What it does concretely

```
Browser → KovZu (Express API) → BRIDGE (local HTTP) → spawn cursor-agent/claude (CLI process)
                                     ↓
                                parses stdout line by line
                                     ↓
                                rebroadcasts via SSE (Server-Sent Events)
```

1. **Receives** `POST /api/inject { conversation, message }` from KovZu.
2. **Spawns** the real CLI binary (`cursor-agent -p "message"
   --output-format stream-json --resume <chatId>`, or equivalent for
   `claude`).
3. **Parses** its stdout output line by line (structured JSON: thinking, tool
   calls, response text…).
4. **Rebroadcasts** these events in real time via SSE (`GET /api/events`) which
   KovZu (the server `timelineBuilder`, see `TIMELINE-SYNC.md`) listens to.
5. **Keeps in memory** the mapping between conversation ↔ `chat_id`/`session_id`
   to be able to `--resume` on the next turn (session continuity).

## Where it lives (outside app backups)

The entire bridge stack lives under **`/opt/bridge/`** — not in `/apps/helm-v2/`.
See [`OPT-BRIDGE.md`](./OPT-BRIDGE.md).

| Engine | Path | Port |
|--------|------|------|
| cursor | `/opt/bridge/cursor/` | **4310** |
| claude | `/opt/bridge/claude/` | **4320** (+ LiteLLM **4330**) |

Each has its **own `.env`** (CLI API key, port, base workspace) because
they are **separate processes with their own shell environment**.
This is a real trap: the agent's text context (generated by the Express API,
which reads `app/.env`) and the real shell where the agent runs (managed by the bridge,
which reads `/opt/bridge/<engine>/.env`) are **two different environments** —
a variable added to one does not necessarily exist in the other. See
[`CONTROL-SCOPE.md`](./CONTROL-SCOPE.md) for a real encountered case (Cloudflare token)
and `REMOTE3/Travaux/handoffs/BULLDOZER-INCIDENT.md` *(outside repo)* for
permissions.

## Why "bridge" and not "the agent"

It performs **no intelligence** itself — no business logic, no
decision. It only opens the HTTP↔CLI bridge and rebroadcasts what happens. All
business logic (timeline, MariaDB, voice, deliverables, orchestration) lives on the
KovZu side (the Express API), never in the bridge.

See also: [`TIMELINE-SYNC.md`](./TIMELINE-SYNC.md) (run_id/seq event contract
stamped by the bridge, consumed by `timelineBuilder`),
[`AGENT-CONTEXT.md`](./AGENT-CONTEXT.md) (stack overview).
