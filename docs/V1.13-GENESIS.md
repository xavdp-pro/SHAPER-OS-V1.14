# V1.13 — GENESIS: every gesture, from experiment to law

> **What this file is.** V1.13 is the architectural release whose changelog is
> one line — *the tree speaks*. This file lists **every gesture** that made
> it: what was tried in the margin, what survived critique, what entered the
> law, and where each change landed. It exists so the release can be
> delivered to ourselves: when we say "c'est bon", this is what we are
> saying it about. Method per the working doctrine: experiments live in a
> sandbox beside the repo (ZEST series), nothing enters the law until it has
> survived adversarial critique, and the human's "on y va" is the graft
> signal.

## The gestures, in order

### The law

1. **Rule 1 amended** — the universe repo grammar `univ-<projet>-<classe>`
   (one-line regex, `-core` floor), the five repo kinds enumerated (base,
   catalogue, class, fork catalogue, fleet map), the mirror rule for Rule 33
   forks, and the meta-rule written down: *the identifier says WHAT;
   structured data says WHENCE and WHERE*. The previous text demanded
   `univ-` on every repo "no exceptions" while the base itself violated it.
2. **Rule 37 born** — lexicon closure (12 words, amend-to-extend), the three
   manifest lineage fields (`perimeter`, `source`, `forkedFrom`), one state
   machine (`DESIRED → RECONCILING → PURRING → DEGRADED`), the ledger as the
   only instance store, tag precedence (fleet default vs ledger truth), the
   fleet map and its laws. Canon count: 48 → **49**, updated in every
   document that stated it.
3. **[`LEXICON.md`](./architecture/LEXICON.md) born** — the one page that
   passes the test: a human juggling four projects or a cold agent must
   answer *where is the truth / who repairs / is everything fine / how is it
   recreated* from this page alone.
4. **[`FLEET.md`](./architecture/FLEET.md) born** — the `fleet.yml` schema
   engraved once (base, catalogue, classes+governedBy, machines), the `-dev`
   bypass law, federation for sovereign forks, PRA reading order. The
   registration guard is declared **TARGET**.
5. **[`UNIVERSE-REPO-BIRTH.md`](./agent/UNIVERSE-REPO-BIRTH.md) amended** —
   fork naming now follows the mirror rule (the old `univ-<class>-<owner>`
   contradicted the projet-first grammar; the fortress archetype forced the
   resolution). The catalogue boundary in one line: *a brick goes to the
   catalogue when its INTENT can be written without the business word*.
6. **PERIMETERS.md amended** — golden rules 4 and 5: *perimeter means LAYER,
   never OWNER*; behaviour files (`ctx-`/`task-`) ride the brick that
   executes them.

### The grammar of the manifest

7. **The schema** (`universe-manifest.schema.json`) — `perimeter` mandatory
   per brick; `source` grows to `base|catalogue|fork|native`; brick-level
   `forkedFrom {package, atVersion}` mandatory-when-fork (JSON-Schema
   if/then); repo-level `forkedFrom {repo, atTag}` for Rule 33 forks; and two
   fields the law already required but the schema **refused**
   (`additionalProperties: false`): `alerting` (Rule 27) and `dataLifecycle`
   (Rule 31). The law and its grammar no longer contradict each other.
8. **Every real manifest updated** — univ-base, _template, tier-a (base) and
   the four catalogue manifests each declare `perimeter` per brick.

### A doctrine lie, caught and corrected

9. **The queue told the truth backwards.** Its INTENT said "in-memory only,
   no persistence" while the code persists JSONL and hydrates at boot. The
   corrected contract (Rule 35 — the constraint, not the anecdote):
   *durability is evidence, never resumption* — a job's record survives a
   crash, its execution does not; at-least-once needs idempotent jobs
   re-enqueued from the universe's own beat. PERIMETERS.md aligned. Found by
   the ZEST4 critics, who caught two archetypes building zero-loss stories
   on the wrong sentence.

### The executable law

10. **Three new checks in `pkg-verify`** — `manifest-lineage` (Rule 37),
    `universe-slug-grammar` (Rule 1), `prod-declares-alerting` (Rule 27 —
    required since before V1.13; what was missing was the check). With their
    tests, each failing on the fixture that reproduces the incident it was
    born from. Coverage, counted honestly: **8 checks — 5 of 49 canon rules
    enforced by machine** (0D, 1, 27, 29, 37), 3 more holding AGENTS.md and
    the Boot Contract. The verifier prints this same split; counting checks
    as canon rules was itself caught by the release review as a
    wrong-denominator claim (Rule 0G).

### The release review (the second pass)

Before publication, three adversarial reviewers (law coherence, cold agent,
mechanical truth) swept the release and returned 25 findings (7+11+7, session log — the workflow artefact itself was ephemeral) — among them:
the birth procedure's own examples contradicted the amended grammar and
failed the new schema; the slug regex accepted `univ-x--`; the verifier's
coverage claim counted checks as canon rules; the schema's fork→forkedFrom
if/then was silently ignored by the subset validator (now enforced as a
pkg-universe invariant, with its test); a dead regex in the catalogue's
orphan-lesson guard; and the fleet map's comment template broke YAML when
uncommented. Every finding was fixed before the tag. A release that reviews
itself and writes down what the review caught is the only kind that can be
delivered to ourselves.

### The ecosystem

11. **The fleet map instantiated** — the operator's `shaper-fleet` repo is
    born beside the base, holding the first `fleet.yml` (base + catalogue at
    `v1.13.0`, machines inventory, no classes yet — they will register at
    birth).
12. **The catalogue follows** — `SHAPER-OS-BRICKS-V1.13`: versions and
    pointers bumped, manifests carry the new fields, alerting declared where
    an environment is beyond dev.

## What V1.13 does NOT do (declared, not forgotten)

Deferred with intent, listed in ZEST4's verdict with their costs: the
`shaper` CLI verb implementation (the contract is in the LEXICON; the tool is
TARGET), the fleet registration guard (TARGET in FLEET.md), `brick-forge`
itself (named, specified by Rule 37, not yet built), the runtime
instance-name grammar (pkg-fleet-dns contract), decommissioning
("funerals" — Rule 31's `onTermination` is the seed), the base-upgrade
ripple story, pkg↔img cross-check, per-universe LLM budget, secret rotation,
concurrent fleet.yml writers, the compact runtime profile debate.

## How this release is proven

The beta protocol, model after model, one at a time: a clean LXC on the test
host, a cold agent (the IDE row of AGENTS.md — Claude Code, Cursor,
Antigravity), the base deployment, then the existing questionnaires
([`COLD-READ-TEST.md`](./agent/COLD-READ-TEST.md),
[`BETA-DEPLOYMENT-TEST.md`](./agent/BETA-DEPLOYMENT-TEST.md)) — **in
report-only mode: the tester reports what worked and what did not, and fixes
nothing**; the fixes are made together afterwards, each climbing back per
Boot Contract 8. You cannot fail the test — only this repository can.
