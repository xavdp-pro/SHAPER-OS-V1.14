# The Living Adaptive Kernel — a design-time reference, never a runtime payload

> **Status**: founding doctrine, stated by the operator on 2 September 2026:
> *"j'ai l'impression que c'est plus un guide structurel pour toi quand on
> dépile ce dont on a besoin pour la mécanique"* — this is a structural guide
> for the architect deriving what the mechanics need, not a text any live
> agent carries.

## What this directory is

Seven documents, co-created by the operator with an outside agent across
several sessions, in three registers of the same material: a full
specification (`SHAPER_OS_LIVING_ADAPTIVE_KERNEL_v0.3_MASTER_EN.md`), the
same content in narrative prose (`THE_LIVING_KERNEL_EXPLAINED_v0.2_EN.md`),
a human onboarding path (`FROM_REALITY_TO_MOVEMENT_HUMAN_GUIDE_v0.2_EN.md`),
and three cognitive-depth guides for agents
(`SHAPER_OS_AGENT_GUIDE_A1_EXECUTOR`, `_A2_REASONER`, `_A3_SYSTEMIC`).

It is intentionally agnostic: no LXC, no podman, no governor, no maker
anywhere in these pages. That is not a gap to close — see
[`../THE-KERNEL-IS-CONSULTED-NOT-CARRIED.md`](../THE-KERNEL-IS-CONSULTED-NOT-CARRIED.md)
for why translating it wholesale into this system's vocabulary would defeat
its purpose.

## How to use it

Read it here, once, when designing a new agent role or reasoning about an
incident. Derive the narrow slice that role actually needs — a STOP list, a
schema, a mechanical check — and encode *that* where the role lives. Never
paste a section of this corpus into a live agent's prompt or system
instructions: the moment this text travels with a running agent instead of
with the person deriving its rules, the kernel has stopped doing its job.
