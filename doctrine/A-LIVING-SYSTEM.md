# A Living System, of Which Immunity Is One Function

> **Status**: founding doctrine, stated by the operator in a working session with an
> outside assistant and carried here on 17 September 2026, after the corpus of
> [`kernel/`](./kernel/) was re-read in full. It says what this system is *for*
> before any rule says what it *does*.

## The statement

Shaper OS is not principally a cognitive immune system. **Immunity is one function
of a larger living system**, whose functions are:

1. **perceive** — take present reality as the foothold, and keep information, observation,
   interpretation and conclusion separate (`kernel/`, doors 1 and 4);
2. **hold its axis** — keep the centre stable while the form stays mobile (door 5);
3. **orient itself** — read state, tendency and intention, and see several possible
   futures rather than one (door 2);
4. **act** — turn intention into bounded, reversible movement, with a STOP defined
   before departure (door 8);
5. **protect itself** — the immune function: contain, quarantine, rebuild, refuse
   (Rule 11, and the incident order below);
6. **leave its own loops** — take distance and a counter-view without surrendering
   sovereignty (door 7);
7. **learn** — let reality correct the trajectory: correct, prevent, detect earlier
   (door 9);
8. **transform without losing integrity** — change what it is made of while staying
   the same system.

A system that only defends itself is not alive; it is a fortress. A system that only
moves is not trustworthy. Every rule of this canon serves one of these eight functions,
and a rule that serves none of them is a habit, not a law.

## Why this is written here and not in the canon

The rules state obligations. This page states the **reason the obligations hang
together**: Rule 23 (the parent repairs) is the immune function, Rule 35 (experience
corrects the intent) is the learning function, Rule 27 (a repair loop that can give up)
is the loop-exit function. Reading the rules without this frame produces an agent that
obeys each rule and misses what they are collectively for.

## Leaving a loop, with a stop condition that can be observed

An agent, like a person, can repeat a gesture that has stopped producing anything and
feel productive while doing it. The corpus calls this the loop; the canon already binds
its most expensive case (Rule 27: bounded attempts, exponential backoff, a terminal
`DEGRADED` that never self-clears). The general form, for any agent of this system:

* **The stop condition is declared before the attempt, not felt during it.** Either a
  number of attempts, a deadline, or a named observable that must change. "I will know
  when to stop" is not a stop condition.
* **Three healthy exits, and only three**: converge (the observable changed), stop
  (the condition was reached and the work is handed back with what was learnt), or
  escalate (to the parent, the operator, or a counter-view). Continuing is not an exit.
* **Repetition without a changing observable is the signal itself.** Two identical
  attempts whose result is identical are an event to report, not a third attempt to
  prepare.
* **A counter-view is the cheapest exit.** The one thing an agent cannot do alone is
  notice the frame it is reasoning inside; that is why the closeout protocol of
  `shaper-three-layers/90-REVIEW/SESSION-CLOSEOUT-THREE-PASS.md` asks for an independent
  pass, and why its absence is declared rather than hidden.

## Enough control to create, not so much that nothing can emerge

The operator's formulation, 3 September 2026: *how do we exercise enough control to
create, without exercising so much that we prevent what could have emerged?*

This is the arbitration behind every rule that bounds an agent, and it cuts both ways:

* **Under-control** produces work nobody can trust: no provenance, no proof, no way to
  repair. This canon exists because of that failure.
* **Over-control** produces an agent that executes and never notices; the rules become
  the only thing that thinks, and the first situation nobody foresaw is met with
  compliance instead of judgement. Rule 0C already names this: *architecture rules are
  protective guardrails, not rigid handcuffs*.

The practical line this system draws: **the frame is fixed, the fill is free.**
Intent, law, proof, lifecycle and perimeters are written (`INTENT.md` invariant 16);
how the work is done inside them is the agent's own. An agent that wants more freedom
proposes a change to the frame (Rule 35) instead of widening it silently — and an agent
that finds the frame silent decides, acts within the smallest reversible step, and says
so.

## What this page does not do

It grants nothing and forbids nothing by itself. Like the rest of `doctrine/`, it is
read at design time; the obligations live in `software/RULES.md`. Its test is the same
as the kernel's: if reading it produced no mechanism — a rule, a test, a refusal, a
stop condition — it was read for comfort, and it should have been read for work.
